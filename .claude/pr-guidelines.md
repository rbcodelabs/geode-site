## Coverage Requirements

Run `npm test` for the marketing-copy checks and supported-plugin registry
contract. There is no E2E suite; the site is static apart from anchor
navigation and the install command's clipboard-copy button. Add browser tests
if the site grows forms, client-side state, or other interactive flows.

## Visual Verification

Whenever any UI is touched, manually verify at these viewports before opening
the PR:

- Desktop: 1280x800
- Tablet: 800x900
- Mobile: 390x844 (iPhone 14)

For each viewport, confirm:
- Layout is not broken (no overflow, no collapsed sections)
- Interactive elements are reachable and usable (nav anchors scroll to the
  right section, copy-to-clipboard button in Install steps works)
- No visual regressions from the diff
- The composed HTML/CSS vault, editor, linked-notes, and workflow illustrations
  remain legible and clearly illustrative at all three viewports
- The docs index, a prose page with a wide table and code block, changelog, and
  supported-plugins catalog remain readable; mobile docs navigation stays compact
- Custom component classes in global.css live inside @layer components -
  plain/unlayered CSS silently wins over Tailwind utilities like `hidden`
  regardless of source order (a real bug hit on the sibling claude-threads-site
  build - keep new component classes inside @layer components too)

## Docs Location

Docs content lives in `src/content/docs/**/*.md`, grouped into five
categories (`overview`, `core-app`, `plugins-api`, `formats-platform`,
`architecture-decisions`) defined in `src/lib/docsCategories.ts`. Source
material is the Geode app repo (`~/projects/geode`): `README.md` for
homepage copy, `docs/spec/*.md` for the core-app/plugins-api/formats-platform
docs, and `docs/adr/*.md` for the architecture-decisions docs. Keep doc
content faithful to the source - light editing (frontmatter, internal link
fixes) is fine, but don't invent new claims about features that aren't in the
source spec/README.

## Changelog

The `/changelog/` page content (`src/content/changelog/*.md`) is generated by
`npm run changelog:generate` (wraps `scripts/generate-changelog.ts`), which
pulls every GitHub Release from the Geode app repo (`rbcodelabs/geode`) via
`gh api ... --paginate` and writes one Markdown file per release, verbatim.
It requires the `gh` CLI to be authenticated (`gh auth status`). Like the
screenshots, this is NOT run automatically as part of the build - the site is
`output: 'static'` and must not depend on live GitHub API calls at build
time. Re-run it manually whenever a new Geode version ships (to pick up the
new release) or to pull in edits to existing release notes on GitHub.
