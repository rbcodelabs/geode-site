## What's New in v0.10.1

### Features

- **Per-vault hotkey management** — Settings now includes a searchable Hotkeys tab where you can assign multiple shortcuts, remove or reset bindings, and filter to commands that currently have shortcuts. Core and plugin commands are supported, and changes take effect immediately in the workspace and Web Viewer. ([#142](https://github.com/rbcodelabs/geode/pull/142))
- **Explicit conflict handling** — when a shortcut is already assigned, Geode names the conflicting command and asks you to cancel or explicitly reassign it. Ambiguous shortcuts fail closed instead of running an arbitrary command. ([#142](https://github.com/rbcodelabs/geode/pull/142))
- **Vault-scoped persistence** — custom bindings are stored in `.geode/hotkeys.json`, isolated between vaults, and restored across relaunches. ([#142](https://github.com/rbcodelabs/geode/pull/142))

### Reliability and accessibility

- Hotkey configuration uses atomic desktop writes and preserves the prior file when a write fails.
- macOS modifier handling now stays consistent across the renderer, main process, and embedded Web Viewer.
- Recording can be canceled with Escape and is cleaned up when Settings changes or closes.
- Hotkey controls expose command-specific accessible names, visible keyboard focus, live status/alert semantics, and non-color conflict labels.
- Command and shortcut labels are rendered safely, including plugin-provided command names.

### Notes

- Recording a new shortcut requires a physical hardware keyboard. Touch-only devices can inspect, remove, and reset assignments.
- Operating-system-reserved shortcuts can be saved, but macOS may intercept them before Geode receives them.
- Native Geode overrides use `.geode/hotkeys.json`; importing Obsidian's `.obsidian/hotkeys.json` is not included in this release.
- macOS builds are ad-hoc signed but not notarized. On first launch, use right-click **Open** or the **Open Anyway** control in Privacy & Security if Gatekeeper warns.
