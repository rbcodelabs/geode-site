## What's New in v0.5.8

### Performance improvements

- **Faster warm launches for large vaults** — Geode now persists its derived metadata cache across launches. Notes whose path, modification time, and size have not changed are restored without rereading and reparsing every Markdown file. New and changed notes still use the existing parser, and deleted notes are removed from the cache. ([#58](https://github.com/rbcodelabs/geode/pull/58))

### Reliability

- Cache writes use atomic same-directory replacement. Missing, corrupt, incompatible, unreadable, or unwritable cache data never prevents a vault from opening; Geode falls back to rebuilding derived metadata from the Markdown source files.
- Stabilized the Bases clipboard end-to-end check so the release gate waits for the asynchronous system clipboard write instead of racing it.

### Documentation

- Updated the README alpha/version labels and documented persistent metadata caching.

### Notes

- No migration or configuration change is required.
- The cache lives under each vault's `.geode/metadata-cache/` directory and is derived data that can be rebuilt safely.
- macOS packages remain ad-hoc signed and are not notarized; follow the existing README instructions for the first launch.
